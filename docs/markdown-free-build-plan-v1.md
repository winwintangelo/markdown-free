## 2. Architecture

| Surface | Runs on | Backend | Cookies | Purpose |
|---|---|---|---|---|
| `markdown.free` | Vercel, **SSG + edge cache** (after Phase −1) | Only `/api/convert/pdf` and `/api/img-proxy` (transient); `/api/convert/docx` remains until Phase 0b | None | Anonymous converter, ~95 → ~150 intent pages, 10 locale landings, template-preset pages |
| `app.markdown.free` | Same Vercel project, `(app)` route group, host-based middleware rewrite | Auth, library, templates, share management, billing UI, `/api/*` for events, reports, Stripe webhooks, share render | Session cookie, **host-only** (no `Domain=` attribute) so the apex stays cookieless by construction | Signed-up + paid |
| `s.markdown.free/<id>` | Same project, `(share)` route group, read-only | Reads the share blob, renders, no scripts from the app | None for viewers | Public share links with "convert your own" credit |
| `markdown.pro` (+ `.app`, `.co` if cheap) | 301 → markdown.free | — | — | Defensive registration; DNS failover if primary is blocked |

Single project, three route groups, one middleware. Why not a second Vercel project: shared `src/lib/markdown.ts`, export libs, dictionaries and e2e fixtures; a monorepo is overhead a solo builder doesn't need yet. Revisit at the self-host trigger (§9).

Cloudflare in front for DNS, WAF, rate limiting at the edge, R2 custom domain, and the failover switch. Vercel stays origin. Verify mainland reachability of the Cloudflare-fronted apex before cutting over (Cloudflare's free tier is sometimes slower from the mainland than Vercel's Anycast).

Handoff between tiers (decided 2026-09-06): after a successful anonymous conversion, one line — "Sign in to keep this" — links to `app.markdown.free/keep#<encoded document>`. The fragment never reaches a server, a log, or a `Referer` header; the app reads `location.hash`, clears it with `history.replaceState`, and holds the document in memory until sign-in completes. Applies to documents under ~100 KB, which is most of them. Larger documents get "sign in, then drop the file again". No wall before value.

## 5. Phases

Effort: S = days, M = 1–2 weeks, L = 3+ weeks, solo with agents. Each phase ends with a gate registered in `data/ledger.json`; the growth loop returns the verdict. Don't start the next phase on a feeling.

**Reality check on sequencing.** Today's base is ~510 conversions/month; the target in §1 needs ~18,000. Accounts + billing (Phase 2) is 6–8 weeks of work that yields ~1 paying customer/month at today's base. Phases 0a and 1 come first because they grow the base and are themselves the differentiator; Phase 1.5 is a two-day demand probe (feature teaser, no prices) that decides whether Phase 2 is worth starting. End to end, Phase −1 through Phase 2 is roughly 5–6 months of solo work if every gate passes, with 0b deferred. **Kill criteria:** if the Phase 1.5 probe fails twice, or conversions have not doubled six months after Phase 1 ships, stop the ladder and switch to plan B (§1).

## 10. Risks

| Risk | Mitigation |
|---|---|
| **OMML / DOCX engine swap fails or balloons** (Phase 0b) | Spike is timeboxed to 1 week with an explicit go/no-go; fallback = keep `html-to-docx`, keep math as images in DOCX, and market "editable equations" only for PDF/HTML/PNG. |
| JP/KR tax registration missed → non-compliant sales | Registrations are a Phase 2 precondition; JPY/KRW checkout stays geo-gated off until done. |
| URL-fragment handoff leaks a document | Fragments are never sent in `Referer` or to servers; the app clears the hash on load; documents over ~100 KB never enter a URL. |
| **Promise change dents SEO CTR** ("Free" and "no signup" are the ranking hooks) | Anonymous promises stay literally true; the sweep is a ledger experiment with CTR as guardrail; rollback is a copy revert. |
| Mainland auth: Google (the must-have path) is blocked there, no WeChat login, flaky email to QQ/163 | Email + password fallback works with zero emails sent; client-side Google reachability check puts the fallback first for mainland visitors; test deliverability with real QQ/163/126 accounts before Phase 2 launch. |
| Vendor absorption (Kimi Docs, Gemini→Docs, OneDrive Markdown) | Quarterly check; value lives in templates/library/merge and fidelity, not single-answer copy. |
| Cookieless apex breaks if someone adds a script or a cookie | CSP on apex (exists: `next.config.js`) plus an e2e assertion that no `Set-Cookie` is ever emitted from apex routes; enforced in CI. |
| Mermaid bundle on mobile (CN is mobile-heavy) | Lazy-load only when a Mermaid fence is present; measure `convert_error` by device. |
| Google scaled-content policy on generated pages | 50 pages with real benchmark data first; no page without a unique benchmark row and hand-checked title. |
| PDF cold starts (5–10 s) feel worse to paying users | Keep PDF server-side for now; watch `pdf_timeout` errors by tier; client-side PDF is a Phase 5 question. |
| Resend 100/day cap blocks signups on a good day | Alert at 60/day; upgrade pre-emptively. |
| Vercel Hobby non-commercial terms | Move to Pro before first payment. |
| Envelope encryption isn't zero-knowledge; share links are server-readable | Publish it honestly; passphrase lock later. |
| Share links used for abuse/spam | Redis rate limit, report link, revoke; Cloudflare bot rules; separate origin. |
| Solo capacity | Every phase has a ledger-scored gate; Phase 1.5 protects the biggest build. |
